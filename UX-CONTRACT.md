# UX Contract

## Product and source ownership

ORDERS_AUTO — русский локальный инструмент закупок, desktop от 1280 px. Работает через `file://`, без сети и сервера. Дата сохраняется в ISO UTC; история показывает местное время браузера с часовым поясом. Цель доступности — WCAG 2.2 AA; автоматические тесты не являются полной сертификацией.

Источники бизнес-правил: `docs/product/SPEC.md`, `docs/data/DATA_CONTRACTS.md`, `docs/data/DERIVED_PROJECTIONS.md`, `docs/ux/UX_AND_EXPORT.md`, `docs/superpowers/specs/2026-10-20-rebalancing-order-integration-design.md`. Приоритет задаёт `AGENTS.md`. Срок хранения/жизненный цикл — раздел полного сохранения сеансов в интеграционном spec; UI не добавляет автоматического удаления.

`DESIGN.md` отражает канонические runtime tokens `src/styles/app.css`; новая функция сохраняет язык существующих Demand/Orders. Единственная тема — светлая рабочая область с тёмной навигацией. Нет внешних шрифтов или ресурсов. Изменения tokens проверяются вместе с CSS и скриншотами sibling screens.

## Navigation and dataset state

Единый рабочий пул поставщиков принадлежит `src/domain/supplierPool.ts`: app selectors, проверка готовности импорта и фильтр потребности применяют его до отображения. SupplierDecisions продолжает использовать общий Select и имеющийся persist-before-publish flow. История и старые overrides сохраняются; недоступный выбор требует решения, не подменяется автоматически. Сохранённый фильтр по поставщику вне пула не применяется. Покрытие: supplierPool.test.tsx и offline.spec.ts.

Порядок: все товары → подразделения → ребалансировка → поставщики → заказы. История доступна отдельно. Последняя страница, фильтры, выбор строк и ширины матрицы сохраняются в IndexedDB. URL не хранит рабочие данные: автономный file:// не имеет серверных маршрутов. Подтверждения и краткие пояснения — временные overlays.

Большие наборы используют VirtualTable; шапка и строки разделяют горизонтальный scroll. Матрица маршрутов сохраняет идентификаторы при горизонтальном scroll. Поиск локальный; очистка немедленная и возвращает фокус. Пустые предложения, отсутствие принятых и отсутствие результата имеют разные сообщения.

VirtualTable сохраняет единый scroll owner для шапки и строк на обычных таблицах. По уточнению23.10.2026 состав перемещения использует тот же primitive небольшими страницами, без горизонтальной и вертикальной прокрутки карточки/таблицы при1280×720,1024×768 и1280×600. Шесть адаптивных колонок группируют количество, справочную цену и сумму; полное название доступно кнопкой через общий Dialog. Высота страницы вычисляется из реальной высоты table frame, измеренной шапки и CSS token `--transfer-row-height`; изменение размеров/ошибка/предупреждение пересчитывает вместимость. Поиск сбрасывает страницу; уменьшение результата ограничивает номер. Выбор страницы меняет только её предложения, принятие — отмеченные позиции текущего поиска на всех страницах. Остальной выбор сохраняется. Шапка, денежные итоги, поиск, страницы и действия всегда доступны. Соседние вкладки сохраняют natural-height/document scrolling. Источник: specs/2026-10-23-transfer-sender-csv-design.md; Chrome E2E09.

Галочки подписаны «Выбрано к принятию» и не меняют принятые/отклонённые строки. «Принять выбранные» доступно во время записи галочек: действие ждёт очередь сохранения, затем открывает подтверждение с актуальной ревизией. Ошибка записи выбора не открывает подтверждение и не принимает строки. В карточке и ячейке матрицы явно показаны сумма перемещения и принятая сумма/строки; верхняя панель содержит общую и принятую суммы по всему плану независимо от поиска. Источник цен — MIN/MAX; отклонённые строки исключены, принятые не дублируются в предложениях, неизвестная цена не превращается в ноль. Evidence: transferAcceptanceQueue, transferDocuments, transferInspector и Chrome E2E09.

Галочка не принимает перемещение. Массовый выбор ограничен видимыми допустимыми предложениями, остальные галочки сохраняются и входят в отдельный счётчик. Отклонение снимает галочку. Принятие ограничено конкретными выбранными строками и требует app-owned подтверждения с изменением закупки/сбросом затронутых ручных количеств.

Переход из пояснения в результаты сохраняет точный SKU и стабильный ID подразделения (любой конец маршрута). Оба ограничения видимы, сохраняются в сеансе и снимаются кнопкой «Сбросить фильтры». Очистка/изменение поиска снимает точное ограничение SKU, сохраняя подразделение. Фильтры не меняют решения по перемещениям и экспортируемые заказы.

Суммы в карточке отправителя охватывают все его направления без фильтров; подпись делает эту область явной. Ячейка направления дополнительно содержит выбранную сумму. Финансовая projection остаётся общей: accepted-source dedup, исключение rejected, неизвестная цена сохраняется неизвестной.

CSV принятых доступен после принятия хотя бы одной строки и содержит весь направленный маршрут, включая скрытые поиском, scope и страницей принятые строки. Он не экспортирует предложения/отклонения и не меняет ledger, закупку или выбор. Кодировка, BOM, ;/CRLF и escaping общие с заказами; цена/сумма справочные MIN/MAX, неизвестные пусты. Runtime owners: export/csv.ts, transferCsv.ts и download.ts; RebalancingPage разрешает маршрут из текущего committed ledger. Ошибка inline, прежнее состояние сохраняется и повтор разрешён.

## Flow ledger

Результаты ребалансировки представлены матрицей направлений: отправители по строкам, получатели по столбцам. Ячейка открывает «Состав перемещения» с теми же drawer styles, portal и useModalLayer, что состав заказа. Количество только для просмотра. Карточка показывает Код1С, артикул, название, единицу, справочную цену MIN/MAX и сумму, остатки/MIN/MAX обеих сторон. Для предложения показано «с принятыми → после принятия только этой строки»; для принятой строки — «по отчёту → со всеми принятыми». Другие непринятые предложения в остатки не подмешиваются. Неизвестная цена остаётся неизвестной; количества разных единиц не суммируются вместе; отклонённые строки не входят в итоги количества и суммы.

Поиск основной матрицы учитывает код, артикул, название и маршрут, включая сохранённый точный SKU/подразделение из поп-апа. Локальный поиск карточки временный, как открытый drawer заказа. Выбор скрытых позиций сохраняется; «Принять выбранные в перемещении» принимает только видимые отмеченные строки этой карточки. Общая кнопка с общим счётчиком продолжает принимать весь отмеченный набор. Подтверждение и ошибки остаются над карточкой. Изменение рабочего снимка или новый расчёт закрывают старую карточку; частичное принятие и отмена обновляют её без двойного учёта. Источник сценария — запрос оператора22.10.2026; физические ограничения и закупка по integration spec20.10 остаются прежними.

## Overlays and resilience

Назначения поставщиков сохраняются последовательно: на время ручного или массового сохранения блокируются конфликтующие выборы, настройки автовыбора и галочки; ручная строка показывает «Сохраняем выбор…». Перед записью автовыбор заново проверяет текущую потребность, кандидатов/цены и защиту ручных назначений. Ошибка сохраняет прежние назначения и выбор строк, управление возвращается для повторной попытки. Блок решений использует отдельные desktop-колонки для галочки, описания SKU и поставщика, toolbar — разнесённые подписи и поля; при узком экране выбор переносится под описание. Evidence: supplierDecisionPersistence.test.tsx; геометрия1280/1024px в offline.spec.ts.

Dialog и useModalLayer — канонический владелец focus trap, Escape, inert background, scroll lock и возврата фокуса; drawers используют тот же hook и portal. Вложенный диалог выше drawer, toast выше диалога; runtime tokens определены в CSS. Длинный текст скроллится внутри ограниченного viewport окна.

Общий toast расположен сверху по центру на всех экранах. Он не закрывает нижние действия карточки или правую кнопку закрытия; E2E09 проверяет отсутствие геометрического пересечения при живом уведомлении, а не только попадание кнопок в viewport.

Сохранение бизнес-состояния — pessimistic: persist, затем publish. useDurableDraft хранит немедленный UI draft условий/поиска/решений и общих настроек порога; команды принятия/расчёта ждут очередь сохранения, при сбое последний draft возвращается к committed state. QuantityInput хранит локальный текст ввода, чтобы быстрый набор не затирался промежуточной записью; количество в расчёте меняется после сохранения. Ошибка возвращает последнее сохранённое значение. Проверка и экспорт ждут завершения записи количества. Команды сериализуются, используют ревизии workspace/accepted ledger. Ошибка записи сохраняет предыдущую версию и показывает постоянное объяснение с повторным открытием сохранённого сеанса. CAS не позволяет другой вкладке молча перезаписать актуальную версию. Импорт имеет отдельное поколение отмены: позднее чтение не возвращает сброшенный сеанс. Никаких автоматических очисток БД или переносов accepted в свежий импорт.

## Приоритеты донора23.10.2026

DonorAllocationDrawer: SKU × допустимый получатель, независимые флажки приоритета, QuantityInput, режим PROPORTIONAL/EQUAL, строки MANUAL и frozen accepted. Один слой модального окна, общий focus trap/Escape/restore. Никаких новых dropdown/input/modal primitives. Страницы по высоте и ширине; действия постоянно видны на1280×720,1024×768,1280×600. E2E-10 проходит реальный импорт → выбор → оба режима → ошибка превышения → ручная правка → принятие → CSV → reload. Доменные тесты проверяют общий резерв нескольких доноров и дробные шаги.

Флажок приоритета и режим используют useDurableDraft для мгновенного отклика и отката при ошибке сохранения; бизнес-план публикуется только после durable commit. После принятия части ручной строки повторный расчёт учитывает её один раз и сохраняет блокировку. Прогноз всей матрицы включает отклонённые предложения с отдельной подписью; E2E-10 проверяет также компактное состояние с ошибкой/отклонением.

Успешное сохранение плана снимает устаревшее уведомление «Изменения не сохранены»; новая доменная ошибка остаётся у поля и в окне донора до следующей правки.
