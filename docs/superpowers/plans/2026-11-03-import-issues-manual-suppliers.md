# Полные сообщения импорта и ручной поставщик без истории

**Goal:** сделать доступными все сообщения импорта и разрешить явное назначение одного из 32 поставщиков товару без доступной истории закупок.

**Architecture / verdict: READY.** Существующие ImportPage, VirtualTable, supplierPool, resolveSuppliers и queued workspace commit уже владеют нужными границами. Новые зависимости и миграция IndexedDB не нужны.

## Требования и технические решения

- Все сообщения обоих отчётов доступны в ограниченной по высоте таблице, без slice. Поиск по сообщению, строке, коду и подразделению; фильтр важности; текстовые уровни и счётчики. Виртуализация принадлежит общему VirtualTable.
- При отсутствии кандидатов в рабочем пуле ручной select предлагает все 32 компании, включая отсутствующие в отчёте поставщиков. При наличии истории сохраняется прежний список исторических кандидатов.
- Явный ручной выбор без истории сохраняется с optional `allowWithoutHistory: true`. Только ручное назначение и компания из рабочего пула могут использовать этот признак. Старый пропавший исторический выбор и AUTO без истории остаются STALE_OVERRIDE до подтверждения.
- Сохранённое назначение остаётся редактируемым. Эквивалентное имя из отчёта используется для сохранения исторической цены и группировки заказов. История не синтезируется. priceDemand сохраняет правило: цена выбранного поставщика из истории, иначе валидная цена MIN/MAX, иначе неизвестная цена и блокировка выгрузки.
- Ручной commit повторно проверяет текущую resolution и допустимость выбора. Ошибка сохранения не меняет закупку; повторный выбор позволяет повторить запись.
- Пул ограничен существующими 32 компаниями. Ребалансировка и денежные фильтры перемещений не меняются.

## Change impact / ownership

ImportIssues — представление ValidationIssue через shared SearchInput, Select, VirtualTable. ImportPage передаёт имя отчёта и issues. SupplierOverride / resolveSuppliers — долговечное явное разрешение отсутствия истории. SuppliersPage — ввод и атомарное сохранение; derive → priceDemand → orders/export продолжают существующий pipeline. Persistence хранит optional поле без изменения schemaVersion.

Проверить сообщения за пределами первого экрана и >100 строк, одинаковые тексты, нулевой результат поиска, смешанную важность; отсутствие цены, нулевую валидную цену, выбор вне пула/AUTO, устаревшее legacy назначение, последующее появление истории, queued replacement и неуспешное сохранение. Восстановление workspace и CSV должны использовать выбранную компанию и существующий fallback, не выдуманную историю.
