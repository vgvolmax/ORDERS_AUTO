# Стабильная шапка и реестр принятых перемещений

## Вердикт — READY

Запрос: одинаковая компактная верхняя панель на всех вкладках ребалансировки, как у «Маршрутов»; новая вкладка «Принятые» справа от «Результатов», прокручиваемые направления с суммой/откуда/куда, фильтры и одиночный/массовый CSV. Причина скачка — route-only CSS selectors для общей шапки/метрик/вкладок.

## Поверхность изменения

Общая CSS-компоновка шапки, RebalancingPage/tab union, новая read-only accepted projection/view, CSV adapter, optional persisted acceptedFilters. Domain allocation/acceptance, ledger и закупка не меняются. Offline/file:// и общий Inter/design tokens сохраняются.

## Технический дизайн

Все общие компактные стили .rebalancing-routes становятся .rebalancing-page, при этом «Условия» сохраняют естественную высоту. Принятый реестр владеет ограниченной высотой и внутренним прокручиванием VirtualTable, без ограничения соседних вкладок.

Принятое решение разработчика, объявленное пользователю: строка реестра — направленная пара отправитель→получатель, как существующий документ матрицы; доступен просмотр всех SKU. Источник только committed accepted, proposal никогда не передаётся в accepted projection. Сумма неизвестна при неизвестной цене, единицы не смешиваются в количествах.

Поиск по коду/артикулу/названию/направлению отбирает целые документы, не режет их состав. Фильтры отправителя/получателя используют branch IDs, сохраняются отдельно от фильтров результатов аддитивным optional полем acceptedFilters без смены схемы. Выбор направлений для экспорта временный, сохраняется при фильтрации внутри вкладки, скрытый выбор явно посчитан. Выбрать по фильтрам действует на весь отфильтрованный список, включая виртуализированные строки. Одиночный CSV повторно использует существующий формат; массовый — один файл с одним заголовком и отправителем/получателем в каждой принятой товарной строке. Ошибка выгрузки видима, выбор не теряется, повтор разрешён.

Сравнение альтернатив: отдельный SKU-реестр создавал бы новый смысл документа и усложнял выгрузку по направлению; ZIP не требуется для запрошенного CSV и добавлял бы лишний шаг распаковки. Реестр направлений + один общий CSV переиспользует текущие проекции и формат.

## Порядок реализации

Projection/export tests → shared accepted-only helpers/CSV → view/filters/selection/composition + shared header → browser geometry, reload and downloads → new PR without merge.

## Проверка

Непринятые/отклонённые строки отсутствуют; фильтр SKU не урезает документ; hidden selection и массовая выгрузка полны; известный ноль/неизвестные суммы сохранены; пустое состояние/повтор выгрузки; восстановление accepted tab/filters; одинаковые координаты шапки и вкладок1280×600/720; длинный список прокручивается и виртуализирован; кнопки доступны с клавиатуры и viewport.
