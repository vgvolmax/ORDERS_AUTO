# Исправления целостности расчётов ·03.11.2026

Основание: пользователь поручил внести пять исправлений после аудита main `0b8e5cd`. Область согласована сообщением «Внеси правки»; технические детали ниже — выбор исполнителя.

Цель: исключить выдуманные цены, готовые заказы из неоднозначных строк и ложную блокировку на точном денежном пороге. Offline/file://, Код1С, рабочий пул, правила Min/Max, accepted-only procurement и совместимость сохранённых сеансов сохраняются.

Подход: исправить источники ошибок и провести диагностику через существующий чистый order pipeline. Альтернативы — запрещать весь импорт при одной ошибке (теряются независимые корректные заказы) либо ограничиться сообщением в импорте (не защищает экспорт) — не подходят. Общий Alert используется для постоянной сводки на экранах потребности/поставщиков/заказов; визуальная система не меняется.

- Неполная/нечисловая стоимость или количество истории не подменяется достоверным нулём при расчёте weightedUnitCost. История сохраняется, weightedUnitCost=null, выдаётся диагностика. Явный ноль и числовые возвраты сохраняются.
- Повторный родительский Код1С диагностируется, конфликтная резервная цена не выбирается по последнему блоку. Повторные физические срезы/ошибочные строки сохраняются как закупочные проблемы, связанные с SKU/подразделением. Заказы с положительной неоднозначной строкой BLOCKED; независимые корректные заказы доступны. Неизвестную потребность не заменяем нулём.
- Для старых нормализованных сеансов повторные SKU/срезы также проверяются при derive; утраченные при прежнем импорте исходные значения восстановить без повторного импорта нельзя.
- Отрицательная/неконечная цена не используется; действующий валидный источник имеет приоритет. При отсутствии валидного источника — null и существующий жёсткий blocker цены.
- Суммы и произведения считаются десятично, без epsilon и без преждевременного округления средневзвешенной цены. Сравнение порога использует точную сумму строк, до преобразования в Number для отображения. CSV/Excel и сводки используют те же денежные helper functions. Правило отображения двух знаков не изменяется.
- Изменение закупки/выбора поставщика сохраняет связанные ограничения данных и адресно инвалидирует review/export markers. Прошлый marker не обходит новую блокировку.

Критерии: каждый пример аудита закреплён регрессией RED→GREEN, контролируется известный ноль/возвраты/независимые корректные заказы; typecheck, весь Vitest, build и Chrome E2E. Изменения в отдельной ветке/PR, без merge.
