# Независимый справочник товаров и поставщиков

Пользователь согласовал независимый справочник и поручил реализацию без слияния.

## Поведение
- При первом запуске MIN/MAX даёт товары, остатки, нормативы и цены; отдельный отчёт поставщиков однократно задаёт связи по полному коду 1С. Пул 32 компаний прежний.
- Справочник живёт в отдельной записи IndexedDB. Он хранит идентичность всех известных товаров, основной/дополнительные связи и исходные сведения отчёта поставщиков для единиц измерения.
- Новый MIN/MAX дополняет товары и обновляет их название/артикул; отсутствующие товары и явно снятые назначения сохраняются. Новые сеансы используют актуальные связи справочника.
- Каждый сеанс сохраняет исторический снимок назначений и исходных отчётов. Просмотр/восстановление истории не переписывает справочник. В восстановленной рабочей копии исторические заказы остаются прежними; явное редактирование связи обновляет справочник и только затронутые коды рабочей копии. Следующий MIN/MAX использует весь актуальный справочник.
- Раздел «Поставщики» редактирует общий справочник, включая отсутствующие в текущем MIN/MAX товары. Показываются фильтр присутствия и текстовое состояние строки. Закупочные суммы и потребность относятся к текущему сеансу.
- Первичная миграция берёт назначения только из активного сеанса; история дополняет исключительно недостающие идентичности товаров. Снятые назначения не восстанавливаются из старой истории. Отсутствие активного сеанса не должно уничтожать уже существующий справочник.
- Запись справочника и затронутого снимка атомарна; публикация только после успешного сохранения. Ревизия справочника защищает от потери изменений в другой вкладке; при ошибке доступен повтор.

## Границы
Домен supplierCatalog владеет объединением товаров и изменениями связей. catalogSession связывает его со снимком, workspaceSession сериализует команды. persistence/supplierCatalog владеет загрузкой и однократной миграцией; saveWorkspace атомарно записывает каталог и снимок. App остаётся точкой сборки. Старые снимки не получают ссылку на изменяемый каталог; catalog присутствует только в AppState.

Без новых зависимостей, сервера, HTTP, изменений расчётов закупки/перемещений, денежных допусков и сверки счетов. Код 1С — единственный ключ. JSON backup и синхронизация AppBox вне этого изменения.

## Приёмка
Создать связи → сменить MIN/MAX → сменить поставщика → восстановить старый сеанс → загрузить новый MIN/MAX: общий справочник содержит новое назначение, архивный заказ — прежнее. Исчезнувший товар доступен для редактирования и возвращается с новой связью. Ошибка записи/устаревшая ревизия не меняют ни справочник, ни снимок. Два стартовых отчёта принимаются в любом порядке, повторный запуск не требует отчёта поставщиков.
