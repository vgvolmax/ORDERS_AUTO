# Актуальный справочник и принятые документы

Решение пользователя: справочник един независимо от сессии; принятие фиксирует документ, непринятые данные используют актуальный справочник. PR64 разрешено смержить, реализацию оформить следующим PR без слияния.

## Результат
- Восстановление старой недели не откатывает справочник. Все рабочие назначения и единицы берутся из текущего каталога; остатки, нормативы и цены MIN/MAX остаются данными выбранной недели.
- Граница фиксации — существующий статус «Принят» у перемещений, на уровне принятой строки. Снимок содержит артикул, название, единицу, цену, поставщика и названия сторон. Количество, идентификаторы и условия уже хранятся в ledger.
- Принятые строки отображаются и экспортируются по своему снимку, даже если справочник изменился. Непринятые предложения и закупочные заказы используют текущие справочные данные. «Проверен»/«Выгружен» не становятся принятием заказа; новый статус для закупок не вводится.
- Отмена принятия удаляет зафиксированную строку; повторное принятие захватывает актуальные данные.
- Проверка и отметка выгрузки непринятых заказов снимаются при фактическом изменении состава/единиц/поставщика. Простое открытие неизменившихся данных их не снимает.
- Сверка заказов из истории применяет тот же текущий каталог, а перед выгрузкой проверяет его ревизию. Исторические физические источники не переписываются.

## Владельцы и подход
Один вертикальный PR с единым риском: граница между текущим справочником и фиксированным документом. `catalogSession` применяет каталог к рабочей копии; `acceptedDocumentContext` захватывает снимки принятых строк; `transferDocuments` проецирует их для UI/экспорта. Форматы CSV/Excel и архитектура file:// сохраняются.

Выбран существующий ledger с аддитивным полем снимка. Отдельное хранилище проведённых документов и новая система статусов не требуются. Замораживание всего периода противоречит принятой построчной логике.

## Совместимость
Старые принятые строки без снимка фиксируются из доступных сохранённых данных своего сеанса до применения live-каталога. Это не восстанавливает исторические значения, уже утраченные до обновления. Пустая/неизвестная цена остаётся null, известный ноль — 0. Старые неизвестные/конфликтные единицы исходной истории не становятся достоверными из-за каталога.

Внутри рабочего расчёта явно заданная единица текущего каталога имеет приоритет над известной единицей старого отчёта; конфликт/неизвестность исходной истории сохраняет прежнюю защиту. Снимки из прошлых версий читаются без повышения schemaVersion.

## Ограничения
AppBoxFiles остаётся ручным обменом JSON; автоматическая межпользовательская синхронизация и shared SDK не добавляются. Изменения на других компьютерах видны после публикации/обновления JSON. Источник истины цен — MIN/MAX выбранной недели, без пересчёта физических количеств между единицами.

## Проверка
RED→GREEN: принятие, изменение каталога, восстановление/перезапуск, смешанные принятые/непринятые строки, отмена и повторное принятие, null/0, архивная сверка, отказ атомарной записи и устаревшая ревизия.
