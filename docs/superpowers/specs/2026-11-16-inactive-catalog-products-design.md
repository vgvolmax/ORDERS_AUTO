# Неактивные товары выбранного MIN/MAX

Согласовано пользователем: отдельное представление отсутствующих товаров,
только просмотр; реализация отдельным PR без слияния.

## Поведение
- Источник активности — полный Код 1С в MIN/MAX выбранного рабочего сеанса.
  Нулевой остаток, отсутствие потребности, цены или норматива не означают
  неактивность. Товар возвращается автоматически при следующем появлении кода.
- Независимый справочник сохраняет идентичность, единицу и все назначения.
  Статус не записывается ни в каталог, ни в shared JSON; миграция не нужна.
- «Поставщики»: «Товары · N», «Неактивные · N», «По поставщикам».
  Первый список содержит только текущие товары. Второй — отсутствующие,
  с поиском по коду/артикулу/названию и фильтрами поставщика/роли/назначения.
  Фильтры двух списков независимы. Счётчики не зависят от поиска.
- Неактивный список показывает единицу, основного и полные имена дополнительных
  поставщиков. Нет выбора строк, назначения, удаления, ручной активации или
  перемещений. Поиск с очисткой, виртуализация и стиль прежние.
- До MIN/MAX оба счётчика неизвестны: «—»; список просит загрузить отчёт.
  После загрузки непустой каталог может иметь ноль неактивных товаров.
  Отдельно различаются пустой список и отсутствие результатов поиска.
- Восстановление сеанса меняет область активности на его MIN/MAX. Рабочие
  назначения остаются актуальными; принятые документы остаются фиксированными.
  Ошибка импорта/сохранения не публикует частично изменённый статус.
- Закупки, разрешения поставщиков, quantity policies и ребалансировка продолжают
  использовать текущий dataset. Никаких новых входов из полного каталога.
  Сводка «По поставщикам» считает связи справочника, деньги — текущего сеанса;
  это различие явно поясняется. Переход из сводки ведёт в активные товары,
  неактивные доступны соседней вкладкой с тем же поставщиком и ролью.

## Владельцы и границы
SupplierWorkspace владеет представлением, счётчиками и выбором активных кодов.
SupplierProducts расширяется вариантом просмотра неактивных; используются
VirtualTable, productColumns, SearchInput и native Select. Нового UI owner нет.
catalogSession/supplierCatalog и расчётный pipeline остаются каноническими.

## Приёмка
Скрытый/сохранённый выбор отсутствующего кода не попадает в массовое назначение.
Одинаковый артикул разных кодов не объединяет товары. Legacy presence-фильтр
не может скрыть весь новый активный список. Reload, смена недели и restore
сохраняют поставщиков и восстанавливают правильное присутствие.

## Альтернативы
Оставить только прежний фильтр — недостаточно заметно для оператора.
Глобальный active-флаг — неверен для разных периодов и сотрудников.
Выбрана вычисляемая область сеанса и существующее табличное представление.
