# ORDERS_AUTO — UX and Export Specification

## Уточнение рабочих экранов30.10.2026

- Каждый раздел сохраняет собственную позицию прокрутки в пределах открытого сеанса. Новый раздел начинается сверху; закрытие диалога сохраняет контекст.
- Таблицы потребности закрепляют код, артикул и наименование; сортировка и видимость остальных столбцов сохраняются отдельно для разделов. Скрытие и сортировка не меняют выбранные позиции.
- Подтверждение перемещений показывает отправителей, получателей, SKU, справочную сумму и закупку до/после. Неизвестная цена обозначается явно.
- Сводки закупки разделяют количества по единицам измерения. Позиции без единицы считаются в SKU.
- Карточки отправителей показывают общую, выбранную и принятую суммы; скрытый фильтром выбор обозначается отдельно. Пропущенные SKU показывают потребность, доступное количество и дефицит с переходом к маршрутам.
- Уведомления явных действий занимают отдельную верхнюю полосу, доступную и при открытом диалоге. Ошибки экспорта сохраняются на экране до следующей попытки; обычное автосохранение не создаёт уведомление.
- Локальная Inter с кириллицей встроена в CSS автономной сборки; лицензия поставляется в FONT-LICENSE.txt. Внешняя загрузка шрифтов не используется.

## 1. Общая навигация

После успешного импорта верхние разделы:

`Все товары | Поставщики | Перемещения | Заказы | Счета`

Подразделения перечислены отдельно в боковой навигации.

Отдельная кнопка `Загрузить новые отчёты` возвращает к импорту после подтверждения, если есть ручные изменения orderQty в текущей сессии.

## 2. Экран «Импорт»

Два file input/dropzone:

- Min-Max (`.xlsx` обязательно; `.xls` можно поддержать дополнительно);
- Поставщики (`.xls` / `.xlsx`).

После parsing показать две карточки качества данных:

- имя файла;
- количество SKU / supplier records;
- найденные подразделения / поставщики;
- warnings/errors;
- для supplier resolution: сколько SKU без поставщика и сколько с несколькими кандидатами.

Кнопка `Перейти к потребности` активна, если оба dataset распознаны. Row-level warnings не блокируют переход.

## 3. Вкладка подразделения

KPI:

- SKU ниже MAX;
- SKU ниже MIN;
- потребность до MAX, количество;
- потребность до MAX, ₽ (сумма известных цен; рядом количество строк без цены).

Таблица:

`Статус | Артикул | Код | Номенклатура | Остаток | MIN | MAX | Не хватает % | Нужно сюда | Нужно всей сети | ₽ сюда | ₽ всей сети | Поставщик | Источник цены`

По умолчанию показывать только позиции `deficitQty > 0` и валидный MAX.

Статусы:

- OK — зелёный;
- YELLOW — жёлтый;
- ORANGE — оранжевый;
- LIGHT_RED — светло-красный;
- BELOW_MIN — бордовый;
- NO_NORM/INVALID_NORM — серый/предупреждение.

Всегда показывать текст, не только цвет.

## 4. Вкладка «Все»

Одна строка на SKU, агрегированная по сети:

`Статус худшего подразделения | Артикул | Код | Товар | Подразделений с дефицитом | Из них ниже MIN | Потребность, ед. | Потребность, ₽ | Поставщик/статус`

Строка раскрывается и показывает подразделения с их stock/MIN/MAX/deficit.

Порядок severity для «худшего статуса»:

`INVALID_NORM > BELOW_MIN > LIGHT_RED > ORANGE > YELLOW > OK > NO_NORM`.

## 5. «Поставщики»

В представлении «Товары» можно искать по коду 1С, артикулу и названию. Фильтры показывают товары с основным и без основного, товары конкретного поставщика в выбранной роли и товары с остаточной потребностью. Назначения можно менять и у товара без потребности.

В представлении «По поставщикам» видны все 32 компании. Счётчики показывают количество товаров с основными и дополнительными связями. Сумма закупки учитывает заказы по основным связям. Нажатие на счётчик открывает соответствующую выборку товаров.

Карточка товара показывает основной и дополнительные связи. При замене основной становится дополнительным. Снятие основного подтверждается отдельно. Массовое назначение показывает число новых назначений и замен и применяется к отмеченным SKU, включая отмеченные строки вне текущего фильтра.

## 6. Общие фильтры

В demand/suppliers/orders доступны:

- поиск по коду, артикулу, названию;
- статусы;
- подразделение;
- поставщик;
- потребность ₽ от/до;
- `minimumOrderAmount`;
- threshold mode `SUPPLIER_TOTAL / BRANCH_SUPPLIER`;
- `Показывать ниже порога`;
- `Только попадающие в заказ`.

Изменение minimumOrderAmount/threshold mode сохраняется локально.

## 7. «Заказы»

Основное представление — матрица:

- строки: поставщики;
- столбцы: подразделения;
- cell: сумма заказа и количество SKU;
- последний столбец: итого поставщику.

Cell states: `READY`, `BLOCKED`, `belowThreshold`, `EXPORTED`.

Клик по cell открывает `OrderDrawer`:

`Артикул | Код | Товар | Остаток | MIN | MAX | Расчёт до MAX | К заказу (editable) | Цена | Источник цены | Сумма | Предупреждения`

Редактирование quantity пересчитывает cell и supplier total немедленно.

### «Счета»

«Сверить счёт» из заказа или матрицы поставщика открывает «Счета» с предварительным выбором. Из меню выбор начинается с текущего сеанса. Смена источника позволяет открыть прошлый сеанс для просмотра без его восстановления.

После выбора заказов оператор загружает Excel, запускает сверку и проверяет расхождения. Корректировка предлагает количества из счёта или заказа и позволяет вручную выбрать строки и задать количество и цену. Итог доступен для копирования и выгрузки в 1С. Счёт и корректировка обрабатываются в памяти открытого экрана.

Если распознано несколько товарных листов, блок «Листы счёта» показывает их названия и число позиций. Начальный выбор пуст, «Сравнить» недоступно до явного применения выбранного набора. Смена листов сбрасывает результат; ручные правки защищены прежним подтверждением. Пропущенные товарные листы перечисляются в замечаниях, источник расхождений содержит лист и строку. Неизвестная единица помечается «Единицы» и требует ручного включения строки в корректировку.

## 9. CSV заказа подразделения

Один CSV соответствует одному order `branch × supplier`.

Filename:

```text
<Подразделение>__<Поставщик>__YYYY-MM-DD.csv
```

Sanitize недопустимые filename characters.

Encoding: UTF-8 BOM. Separator: `;`. Line endings: CRLF.

Колонки в строгом порядке:

```text
Код;Артикул;Номенклатура;Подразделение;Поставщик;Количество;Ед.;Цена;Сумма
```

Экспортируется `orderQty`, не `calculatedQty`.

Кнопки:

- скачать CSV выбранного заказа;
- `Скачать все CSV` → ZIP только для видимых/READY заказов, если пользователь не включил явный экспорт blocked-заказа.

## 10. Excel поставщику

Один `.xlsx` на одного поставщика.

Filename:

```text
<Поставщик>__Заказ__YYYY-MM-DD.xlsx
```

### Лист `Общий заказ`

Верхний KPI-блок:

- Поставщик;
- Общая сумма;
- Количество SKU;
- Количество подразделений;
- Общее количество единиц.

Ниже агрегированная таблица, одна строка на SKU:

`Код | Артикул | Номенклатура | Всего количество | Ед. | Цена | Сумма`

Если один SKU идёт в несколько подразделений, количество суммируется.

### Листы подразделений

По одному листу на каждое подразделение, где есть orderQty > 0:

`Код | Артикул | Номенклатура | Количество | Ед. | Цена | Сумма`

Excel sheet names sanitise `[]:*?/\\` и обрезаются до 31 символа; collisions разрешаются стабильным suffix.

Workbook должен иметь freeze panes, header styling, currency/number formats, autofilter и разумную ширину колонок.

## 11. Экспорт и blockers

По умолчанию export запрещён для заказа с:

- unresolved/multiple supplier;
- missing price;
- invalid norm;
- belowThreshold.

UI может предложить явный `Экспортировать несмотря на предупреждение` только для `belowThreshold` и `orderQty > calculatedQty`. Нельзя bypass supplier/price blockers.

После подтверждённой выгрузки заказа ниже порога интерфейс отдельно показывает «Выгружен» и текущее ограничение. Такой заказ остаётся исключённым из массовой выгрузки по порогу.

### Порог по подразделению-получателю ·03.11.2026

Настройка называется «Сумма SKU у одного получателя не ниже порога». Рядом явно объясняются потребность до выбранной цели, включительная граница и объединение доноров только внутри одного получателя. Денежные исключения показывают адресное подразделение; суммы других получателей не позволяют пройти фильтр/принятие. Экспорт/заказ по-прежнему учитывает только принятые строки.


### Минимальная сумма SKU в перемещении ·03.11.2026

Один денежный фильтр: «Минимальная сумма SKU в перемещении», поле «Порог суммы SKU». Второй фильтр цены единицы удалён. Помощь объясняет: количество одного SKU×цена MIN/MAX проверяется отдельно для донор→получатель; равенство проходит; другие SKU/доноры/получатели не складываются. Строки ниже порога исключаются, остальные сохраняются, остаток доMAX остаётся в закупке после принятия. Исключения показывают SKU, отправитель→получатель, сумму и порог. Ошибка принятия указывает, что конкретный SKU в направлении не набрал минимум. XLSX содержит обе стороны/сумму/порог исключения и актуальное объяснение правила.


### Реестр принятых и стабильная шапка ·03.11.2026

«Принятые» справа от результатов: одна строка на направленную пару, сумма/отправитель/получатель/состав SKU/CSV; список прокручивается внутри viewport и виртуализируется при большом числе направлений. Поиск и два native Select, сброс, сортировка суммы/сторон. Поиск отбирает целое направление, CSV содержит все его принятые товары. «Выбрать по фильтрам» охватывает все отфильтрованные направления, включая виртуализированные. Выбор скрытых направлений сохраняется, скрытый счётчик явный; массовый CSV включает весь отмеченный набор. Выбор экспорта временный, фильтры и вкладка сохраняются. Состав read-only в общем Dialog, ошибки экспорта видимы в активной поверхности, повтор не теряет выбор. Общая шапка соответствует прежней компактной высоте Routes; Conditions сохраняет естественную высоту.


### Массовая отмена принятия ·03.11.2026

В реестре: фильтры→выбрать по фильтрам→«Отменить принятие (N напр.)»; область — все отмеченные направления, скрытый выбор показан. В составе: поиск SKU→«Принятые по поиску» либо индивидуальные checkbox→«Отменить принятые (N)». Область — выбранные принятые строки текущего поиска, hidden count предупреждает об исключённых из действия. Количества accepted остаются неизменяемыми; отмена только через существующее подтверждение с суммой/числом строк/закупкой. Строки предложений и их принятие отделены от отмены. Кнопка-индикатор потребности «Перемещения (N)» — одна строка, число не переносится; label может аккуратно сокращаться в узкой ячейке, полный смысл сохранён в aria-label и tooltip.


### Сообщения импорта ·03.11.2026

Обе карточки импорта показывают полный набор ValidationIssue в таблице с внутренней прокруткой до320px. Одинаковые сообщения не объединяются. Более100 строк виртуализируются общим VirtualTable; поиск работает по всему набору.

### Неполное покрытие и диагностическая прозрачность · 06.11.2026

На экране перемещений «К перемещению» показывает непринятые и неотклонённые предложения; «Не распределено» показывает `sum(missingQty)` по SKU после новых предложений, а не весь объём потребности SKU. В списке нераспределённого: «Нужно» — потребность до новых предложений, «Предложено» — сумма допустимых строк плана, «Осталось» — непокрытое количество, которое впоследствии остаётся к закупке при принятии плана. Справочная сумма остатка = `missingQty × referencePrice`. В Excel лист «Не распределено» и детализация получателей отражают те же значения; неизвестная цена остаётся неизвестной. Предложения не уменьшают закупку до принятия пользователем.

### Еженедельное обновление MIN/MAX и работа с назначениями

Первый запуск принимает MIN/MAX и стартовый отчёт поставщиков. После настройки «Обновить MIN/MAX» открывает выбор одного файла. Рабочий снимок меняется после успешной проверки и записи. История сохраняет предыдущий снимок с его связями, заказами и принятыми перемещениями.

Во вкладке «Поставщики» представление «Товары» показывает текущий каталог независимо от наличия потребности. Фильтры различают наличие основного и роль выбранного поставщика. В карточке товара меняются основной и дополнительные поставщики. Представление «По поставщикам» показывает фиксированный пул, сводку и переход к отфильтрованным товарам. Массовое назначение действует на явно выбранные SKU.

Экспорт заказа сверяет активную ревизию непосредственно перед скачиванием. При конфликте вкладок оператору предлагают открыть актуальную версию.

### Обработка и выгрузка перемещений · 11.11.2026

В составе направления редактируется количество предложенной строки. Цена и сумма отображаются отдельно. Компактная ссылка «Направления N» открывает список по тому же коду 1С во всём сеансе: маршрут, количество, решение и лимит для правки. Состояние плашки считается по полному составу направления: все отклонены — бледно-красная, все обработаны и есть принятые — зелёная, остались предложения — нейтральная. Счётчик отклонений выделен красным.

Рабочий XLSX из «Принятых» содержит «Сводку» и отдельный лист на каждую выбранную пару отправитель → получатель. Берётся весь принятый состав выбранных направлений. Код 1С хранится как текст, количество и деньги — числа. Для CSV используются десятичные запятые. Общий «Excel перемещений» остаётся отчётом с предложениями и решениями.


### Независимый справочник · 11.11.2026

Раздел «Поставщики» показывает все известные товары. Фильтр «Наличие в MIN/MAX»: все / есть в текущем / нет в текущем. Строка явно сообщает присутствие; отсутствующий товар доступен для назначения поставщиков, но не создаёт закупочную потребность. Сводка поставщиков считает связи по всему справочнику, суммы — по текущему сеансу. Текст рядом с действиями объясняет, что архивные сеансы не меняются. Сохраняются прежние Select, Button, Dialog и VirtualTable, без новых токенов. При ошибке сохранения диалог остаётся открыт для повтора.
